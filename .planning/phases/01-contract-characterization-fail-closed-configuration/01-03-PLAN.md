<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Operator mode/path arguments → seed/reset filesystem | A destructive demo command can otherwise clear a pilot SQLite file. |
| Docker environment/volume → startup shell and app | Container mode controls whether synthetic initialization and protected serving occur. |
| Runtime app state → unauthenticated HTML/health consumers | Mode and synthetic/outbox claims are visible to users and probes and must not leak sensitive data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01-10 | Tampering | `careflow.seed` reset path | mitigate | Check mode and resolved pilot path before opening `SQLiteStore`; refuse all pilot/reset attempts without an override. |
| T-01-11 | Denial of service | Docker pilot volume | mitigate | Gate first-start seeding strictly on `CAREFLOW_MODE=demo`; pilot startup never clears or populates the mounted data path. |
| T-01-12 | Information disclosure | HTML banner/readiness/docs | mitigate | Render only mode/synthetic/outbox claims; tests assert absence of secrets, raw paths, patient content, claims, and message bodies. |
| T-01-13 | Elevation of privilege | Pilot landing/demo links | mitigate | Do not render demo links and retain API route gating from Plan 02 when mode is pilot. |
| T-01-14 | Repudiation | Seed summary/outbox state | mitigate | Keep deterministic synthetic summaries, preserve audit/consent rows, and assert `queued` is never described or mutated as sent. |
</threat_model>
